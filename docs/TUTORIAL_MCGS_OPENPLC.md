## 〇、系统架构与前提

```
┌──────────────────┐   Modbus TCP :1502    ┌─────────────────────────┐
│  MCGS 触摸屏/PC   │ ────(FC3读/FC6写)───▶ │  Virtual-Smart-Factory   │
│  (莫迪康驱动,主站) │                       │  ModbusSlave(pymodbus)   │
└──────────────────┘                       │  + Flask大屏(5080)       │
                                            │  + WebSocket(5081)      │
┌──────────────────┐   Modbus TCP :1502     └─────────────────────────┘
│  OpenPLC Runtime  │ ◀────(FC3轮询)──────────────┘
│  (梯形图,主站+从站)│ ────Modbus TCP :5020────▶ ┌───────────────────┐
│  %QX0.0=补料请求  │      (FC1读线圈)          │ plc_refill_bridge.py│
└──────────────────┘                           │ 线圈上升沿→REST补料 │
                                                └─────────┬─────────┘
                                                          ▼ POST /api/command
                                                    虚拟产线料仓补料
```

**共同前提**：
1. 启动产线：`python main.py --web --speed 10`（保持运行）
2. 浏览器打开 `http://127.0.0.1:5080` 备查；接口 `http://127.0.0.1:5080/api/modbus/map`
   返回权威寄存器映射表——**任何地址不确定时以它为准**
3. Windows 防火墙首次放行 Python 网络监听

## 一、MCGS 组态屏联动（预计 1~2 小时）

### 1.1 准备
- 有 TPC 真屏：用学校授权的 MCGSE 嵌入版组态环境，最后下载到屏；
- 没有真屏：装 **MCGS 通用版**（昆仑通态官网提供安装包），全部操作在本机模拟环境完成。
- 本教程两种版本通用，差异处会标注。

### 1.2 建立设备通道
1. 新建工程 → 【设备窗口】→【设备工具箱】→【设备管理】→ 双击添加
   **莫迪康ModbusTCP**（在网络设备分类下；嵌入版叫"莫迪康ModbusTCP"同款）。
2. 双击已添加的设备，进入设备编辑窗口，设置属性：
   - 设备地址（IP）：`127.0.0.1`
   - 远端端口：`1502`
   - 从站号（站号）：`1`（我们的从站 single=True，任意号都响应，填 1 最规范）
   - 其余（超时/轮询周期）默认即可
3. 增加【设备通道】——选"4 区（4x，保持寄存器）读写"，按下面的对照表逐条添加：

| 用途 | 协议地址 | MCGS 里填写的通道号 | 属性建议 |
|---|---|---|---|
| ASM 状态码 | 16 | **40017** | 只读 |
| ASM 故障标志 | 17 | 40018 | 只读 |
| ASM 压装力(0.01kN) | 25 | 40026 | 只读 |
| ASM 扭矩(0.01N·m) | 26 | 40027 | 只读 |
| ASM 料仓余量(0.01件) | 28 | 40029 | 只读 |
| ASM 三色灯绿 | 27 | **40028** | **读写** |
| WH 状态码 | 42 | 40043 | 只读 |
| VIS 剔除挡板 | 39 | 40040 | 只读 |

> 📌 **4x 地址换算规则**：莫迪康驱动按 Modicon 惯例用 1 基显示号，
> 即 `MCGS通道号 = 协议地址 + 1`（协议地址 16 → 填 40017）。
> 不同批次驱动可能存在 ±1 差异——**验收方法见 1.4，对不上就整体 ±1 重试**。

### 1.3 用户窗口组态（画面元件清单）
| 元件 | 绑定通道 | 显示处理 |
|---|---|---|
| 数字显示 ×1 | ASM压装力 | 直接显示原始值，标签写"压装力(0.01kN)"；进阶可用脚本除以100 |
| 数字显示 ×1 | ASM料仓余量 | 同上，标签"料仓余量(0.01件)" |
| 指示灯 ×1 | ASM状态码 | 可见度/颜色表达式：`=2 绿色常亮`、`=3 红色闪烁`、`=1 黄色` |
| 指示灯 ×1 | WH状态码 | 同上 |
| 按钮 ×2 | ASM三色灯绿 | 按下执行"写通道=1"/"写通道=0"（做开灯/关灯两颗）|
| 标签若干 | — | 单元名/说明文字 |

### 1.4 验收清单（全过才算通）
- [ ] 压装力数值随产线节拍变化（压装步爬升到 ≈5000 即 50kN×100）
- [ ] 状态码与 Web 大屏一致（运行中=2；点急停后变 3）
- [ ] 料仓余量递减到 2000（20 件）附近触发低水位告警事件（Web 大屏同步可见）
- [ ] **写回实验（正确姿势）**：先在大屏点【暂停】→ 再按 MCGS 的"开灯"按钮
      → 大屏流程图三色灯变绿 + `/api/status` 中 do_stack_g=1 → 点【恢复】后
      顺控接管、按步重新驱动。
      > 💡 为什么必须暂停？运行中顺控每拍都会刷新输出点——外部写会被覆盖。
      > 这正是"手自动切换"语义的教学现场，对应面试案例《外部写值被冲掉》。
- [ ] 全部通过后截图存档（README 素材）

### 1.5 常见坑
| 现象 | 原因与解法 |
|---|---|
| 连接不上 | 防火墙拦截 Python 监听 → 放行；或产线没启动 |
| 读到的值像错位一格 | 驱动 4x 地址基差 → 整体 ±1 重试并记录你的驱动口径 |
| 写了没反应 | 运行中被顺控覆盖 → 见 1.4 写回实验的正确姿势（先暂停） |
| 数值跳变乱码 | 通道类型选成了 3 区(输入寄存器) → 改回 4 区读写 |

## 二、OpenPLC 梯形图接入（预计 2~3 小时）

### 2.1 安装
1. OpenPLC Editor（写程序）：官网 openplceditor.com 下载 Windows 版，安装即用；
2. OpenPLC Runtime（运行时）：openplc.github.io 下载 Windows 安装包，
   装完自动注册服务，浏览器打开 `http://localhost:8080`，
   默认账号密码均为 `openplc`。
3. 登录后在【Settings】确认两项：
   - **Modbus Slave Port** 改为 `5020`（默认 502 与特权端口冲突，且避开我们 1502）
   - 记住 Start Slaves 按钮位置（后面要启动从站）

### 2.2 梯形图程序（OpenPLC Editor）
新建工程，程序逻辑（先用 ST 表达，画梯形图时一一对应）：

```iecst
PROGRAM MainPLC
  VAR_INPUT                      (* 由 Runtime 主站轮询 VSF 后自动装载 *)
    feeder_raw AT %IW0 : WORD;   (* ASM料仓余量×100 ← VSF 寄存器 28 *)
    asm_state AT %IW1 : WORD;    (* ASM状态码       ← VSF 寄存器 16 *)
  END_VAR
  VAR_OUTPUT
    refill_req AT %QX0.0 : BOOL; (* 补料请求线圈 → 被 plc_refill_bridge 消费 *)
    fault_lamp AT %QX0.1 : BOOL; (* 故障指示灯 → OpenPLC 界面/ScadaBR 观察 *)
  END_VAR

  (* 料仓滞回补料：低于20件置位，补到60件以上才撤销 —— 与产线低水位滞回同思想 *)
  IF feeder_raw < 2000 THEN
    refill_req := TRUE;
  END_IF;
  IF feeder_raw > 6000 THEN
    refill_req := FALSE;
  END_IF;

  fault_lamp := (asm_state = 3);  (* ASM 故障 → 故障灯 *)
END_PROGRAM
```

梯形图画法（两条支路）：
- 支路1：常开触点 `%IW0 < 2000`（比较触点）→ 输出线圈 `%QX0.0` 置位(S)；
- 支路2：常开触点 `%IW0 > 6000` → 线圈 `%QX0.0` 复位(R)；
- 支路3：比较触点 `%IW1 = 3` → 线圈 `%QX0.1`。

编译通过后，导出 `.st` 文件备用。

### 2.3 配置主站轮询（Runtime Web 界面）
1. 【Programs】上传 2.2 编译的程序文件；
2. 【Hardware】选择默认空白层；
3. 【Modbus Master】→ Add new request，添加两条轮询：
   | 名称 | IP | 端口 | 从站号 | 功能码 | 起始地址 | 数量 | 映射 |
   |---|---|---|---|---|---|---|---|
   | 读ASM料仓 | 127.0.0.1 | 1502 | 1 | Read Holding Registers(03) | 28 | 1 | `%IW0` 起 |
   | 读ASM状态 | 127.0.0.1 | 1502 | 1 | Read Holding Registers(03) | 16 | 1 | `%IW1` 起 |
   > 不同版本映射入口略有差异：有的在请求里直接指定起始 %IW，有的按顺序填充。
   > **验证方法**：启动后看监控页 `%IW0` 是否≈大屏料仓件数×100 且实时变化。
4. 回【Dashboard】→ Start PLC；再 Start Slaves（把我们 5020 从站拉起来）。

### 2.4 验收清单
- [ ] OpenPLC 监控页 `%IW0` 数值随产线消耗实时下降（≈大屏料仓余量×100）
- [ ] 料仓跌破 2000 后 `%QX0.0` 变 TRUE（监控页可见）
- [ ] 手工把料仓补满一次（大屏命令或等桥接），回升越过 6000 后 `%QX0.0` 自动 FALSE
- [ ] 点大屏【急停】→ `%QX0.1` 变 TRUE，复位后熄灭

## 三、闭环：plc_refill_bridge.py（预计 30 分钟）

前两章打通后，只差最后一环——把 OpenPLC 的"补料请求线圈"翻译成产线的补料动作：

```bash
python plc_refill_bridge.py            # 默认连 127.0.0.1:5020，轮询线圈 %QX0.0
python plc_refill_bridge.py --once     # 只检测一轮（调试用）
```

脚本行为：每秒读一次 OpenPLC 线圈 `%QX0.0`；**上升沿**（FALSE→TRUE）触发一次
`POST http://127.0.0.1:5080/api/command {"cmd":"feeder_refill"}`——
补料动作走的是正式命令链路，自动落 ui.command 审计事件。

**全链路验收（终极演示镜头）**：
1. 三端全部运行：产线 + OpenPLC(Runtime+Slaves) + 桥接脚本
2. 盯着三个画面：OpenPLC 监控页(%IW0/%QX0.0) → 桥接控制台 → Web 大屏料仓数字
3. 料仓降到 2000 以下 → 线圈吸合 → 桥接打印"检测到补料请求"→ 大屏弹出
   "料仓补料 +60"提示 → 余量回升 → 越过 6000 后线圈释放
4. **录屏这段**——这就是你简历视频的高潮镜头："梯形图做的补料决策，经
   Modbus 双向链路驱动了整条虚拟产线。"

## 四、常见问题速查

| 现象 | 处理 |
|---|---|
| OpenPLC 主站轮询一直失败 | VSF 没启动/防火墙拦 1502；从站号填了非 1 也应能通(single=True)，仍失败则改回 1 |
| `%IW0` 恒为 0 | 主站映射起始地址配错（应为寄存器 28）；用 /api/modbus/map 复核 |
| 线圈吸合但桥接无反应 | 桥接连的端口不是 5020；或 Runtime 的 Slaves 没点 Start |
| 补料风暴（连续触发） | 正常现象检查滞回：只有越过 6000 才会撤销；若料仓上限被补满仍未撤，检查 %IW0 映射是否错读了别的寄存器 |
| MCGS/O​penPLC 同时连 1502 报忙 | 不会冲突——从站支持多客户端并发；若异常重启产线即可 |
